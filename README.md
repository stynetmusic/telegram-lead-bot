# Telegram Lead Bot

Бот для небольшого бизнеса: клиент оставляет заявку в Telegram, бот сохраняет её в SQLite, администратор смотрит заявки, меняет статус и выгружает список в Excel.

Проект учебный и при этом рассчитан на реальную схему работы: отдельный токен, список администраторов, проверка данных и хранение заявок между перезапусками.

## Назначение

Бот заменяет приём заявок в личных переписках. Клиент проходит короткий сценарий. Администратор видит только те заявки, которые уже подтверждены, и может отдать их в работу или выгрузить для отчёта.

Обычный пользователь не получает доступ к списку заявок, карточкам, статусам и файлу Excel.

## Возможности

Клиент:

- получает инструкцию по команде `/start`;
- создаёт заявку командой `/new`;
- по очереди указывает имя, отправляет свой телефон кнопкой Telegram и описывает задачу;
- видит итог и сам подтверждает сохранение;
- получает уникальный номер заявки.

Администратор, чей Telegram ID указан в `ADMIN_IDS`:

- открывает меню `/admin`;
- смотрит последние заявки командой `/leads`;
- открывает карточку командой `/lead_ID`;
- меняет статус командой `/status_ID`;
- выгружает все заявки командой `/export`.

Статусы заявки: «Новая», «В работе», «Выполнена». Новая заявка всегда создаётся со статусом «Новая».

Заявки лежат в файле SQLite. По умолчанию база и каталог Excel создаются на внутреннем диске macOS: `~/Library/Application Support/Stynet/TelegramLeadBot/`. Файл базы — `leads.db`, выгрузки — каталог `exports`. Каталоги создаются при запуске или при `--check` и не попадают в каталог исходников. Другой путь задаётся переменными `DATABASE_PATH` и `EXPORT_DIR`.

## Установка

Нужен Python 3.10 или новее. Проект проверен на Python 3.14.2 с aiogram 3.31.0 и openpyxl 3.1.5.

```bash
cd /path/to/telegram-lead-bot
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
```

Вместо editable-установки можно поставить зависимости отдельно:

```bash
python -m pip install -r requirements.txt -r requirements-dev.txt
```

Тогда команды нужно запускать из корня проекта: пакет ищется через `src` в настройках pytest, а для бота нужен `PYTHONPATH=src`.

## Настройка .env

```bash
cp .env.example .env
```

Файл `.env` не должен попадать в общий доступ. В репозитории остаётся только `.env.example` без настоящего токена.

Переменные:

| Переменная | Обязательна | Смысл |
| --- | --- | --- |
| `BOT_TOKEN` | да | Токен бота от BotFather |
| `ADMIN_IDS` | нет | Telegram ID администраторов через запятую |
| `BUSINESS_NAME` | нет | Название в приветствии. По умолчанию «Сервис заявок» |
| `DATABASE_PATH` | нет | Путь к SQLite. По умолчанию `~/Library/Application Support/Stynet/TelegramLeadBot/leads.db` |
| `EXPORT_DIR` | нет | Каталог Excel. По умолчанию `~/Library/Application Support/Stynet/TelegramLeadBot/exports` |
| `TIMEZONE` | нет | Часовой пояс показа дат. По умолчанию `Europe/Moscow` |
| `LOG_LEVEL` | нет | `DEBUG`, `INFO`, `WARNING`, `ERROR` или `CRITICAL` |
| `LOG_FILE` | нет | Файл журнала. Если пусто, журнал идёт только в консоль |

Уже заданные переменные окружения важнее значений из `.env`.

Свой числовой ID удобно узнать так: запустить бота, написать ему `/id`, вписать номер в `ADMIN_IDS` и перезапустить процесс. Пока ID нет в списке, административные команды недоступны.

## Получение Telegram Bot Token

1. Откройте в Telegram официального бота [@BotFather](https://t.me/BotFather).
2. Отправьте `/newbot` и следуйте вопросам: имя и уникальное имя пользователя, которое заканчивается на `bot`.
3. BotFather пришлёт токен вида `123456789:AA...`.
4. Вставьте его в `.env` в строку `BOT_TOKEN=`.
5. Не отправляйте токен в чаты, не кладите его в код и не коммитьте `.env`.

Если токен утёк, в BotFather есть команда `/revoke`, которая выпускает новый и отключает старый.

## Запуск

Проверка конфигурации и базы без подключения к Telegram:

```bash
python -m leadbot --check
```

При корректном `.env` команда печатает пути, часовой пояс и числовые ID администраторов. Токен она не печатает и к Telegram не обращается.

Обычный запуск:

```bash
python -m leadbot
```

Бот работает через long polling, пока процесс не остановлен. Остановка: `Ctrl+C`.

Если `BOT_TOKEN` не задан или имеет неверный формат, процесс завершается с кодом `2` и пишет, что именно исправить. Значение токена в это сообщение не входит. База при отсутствующем токене не создаётся.

Запускайте команду из корня проекта, если пути в `.env` относительные.

## Команды

### Клиент

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие и инструкция |
| `/new` | Новая заявка: имя, контакт, описание, подтверждение |
| `/cancel` | Прервать заполнение, ничего не сохраняя |
| `/id` | Показать свой числовой Telegram ID |

Телефон принимается только кнопкой «Поделиться контактом», и только если Telegram передал владельца контакта и этот владелец совпадает с отправителем. Номер текстом, чужой контакт и контакт без `user_id` отклоняются. Бот просит нажать кнопку и отправить свой номер.

Пока клиент не нажмёт «Сохранить», заявка в базу не записывается. Повторное нажатие «Сохранить» не создаёт вторую заявку. «Отменить» удаляет черновик. Если запись в базу не удалась, черновик остаётся, и сохранение можно повторить.

### Администратор

| Команда | Действие |
| --- | --- |
| `/admin` | Меню и кнопки «Последние заявки» и «Выгрузить Excel» |
| `/leads` | Последние 10 заявок без телефонов |
| `/lead_12` | Карточка заявки №12, включая телефон |
| `/status_12` | Выбор нового статуса кнопками |
| `/export` | Файл Excel со всеми заявками |

Номер в команде — это числовой номер заявки: `/lead_12`, а не `/lead 12`. Команды `/lead` и `/status` без номера подсказывают формат, но только администратору.

В карточке и в списке даты показаны в часовом поясе `TIMEZONE`. В базе они хранятся в UTC.

## Тесты

Тесты не обращаются к Telegram и не требуют настоящего токена. Имена, телефоны и описания в них вымышленные.

```bash
source .venv/bin/activate
pytest
```

Проверяются создание заявки, обязательные поля, сохранение между повторным открытием базы, статусы, права администратора и клиента, Excel, некорректные данные и запуск без токена.

## Ограничения и безопасность

- Бот отвечает только в личных сообщениях.
- Один процесс, режим long polling. Webhook не используется.
- SQLite подходит для небольшого потока заявок. Обращения к базе и сборка Excel выполняются в рабочих потоках, чтобы не блокировать цикл событий надолго.
- Клиент не может просмотреть свои прошлые заявки. Учёт ведёт администратор.
- Бот не присылает администратору отдельное уведомление о новой заявке. Новые строки видны в `/leads` и в `/export`.
- Контакт без `user_id` и чужой контакт отклоняются. Номер текстом не принимается.
- Повторное подтверждение одной заявки не создаёт вторую запись: события одного пользователя идут по очереди, а обработчик сохранения держит замок до конца записи.
- Если SQLite не смог включить WAL, в журнал пишется предупреждение с причиной и фактическим режимом. Токен, телефон и текст заявки в это предупреждение не попадают. Неизвестный режим журнала останавливает операцию.
- В журнал не пишутся токен, телефон, имя и текст заявки. Служебные сообщения содержат номер заявки и ID пользователя Telegram. Если токен всё же попадёт в строку журнала, форматтер его затирает.
- Пользовательский текст экранируется в HTML-сообщениях. В Excel значения, которые начинаются с `=`, `+`, `-` или `@`, записываются как текст, чтобы таблица не восприняла их как формулу.
- Запросы к SQLite используют параметры, а не склейку строк.
- `.gitignore` закрывает `.env`, базы, журналы, каталог `data/` и файлы Excel.
- Файл экспорта содержит персональные данные. Его не нужно отправлять посторонним и не нужно хранить в открытом каталоге.
- Не публикуйте базу и журналы. Для демонстрации достаточно тестов и вымышленного `.env`.
